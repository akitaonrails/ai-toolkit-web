# Languages

The site is published in English, Brazilian Portuguese, Spanish, Hebrew, Japanese and Korean, the same set as aijail.io. English is the default and the fallback: a string with no translation shows in English, so a missing translation never breaks a page.

| Language | URL | Direction |
|---|---|---|
| English | `/` | left to right |
| Português (Brasil) | `/pt-br/` | left to right |
| Español | `/es/` | left to right |
| עברית | `/he/` | right to left |
| 日本語 | `/ja/` | left to right |
| 한국어 | `/ko/` | left to right |

## How it is put together

| Piece | Where | What it does |
|---|---|---|
| Language list | `src/i18n/languages.json` | Code, names, `lang`, direction, Open Graph locale, browser languages that map to it. Pages, `astro.config.mjs` and the scripts read this one file |
| Messages | `src/i18n/locales/<locale>/<namespace>.json` | One namespace per page, plus `common` (nav, footer, social), `articles` (blog post titles and summaries) and `images` (diagram labels) |
| Lookup | `src/i18n/index.ts` | `useI18n(Astro, 'home')` gives `t()`, `raw()`, `href()`, `date()`, `number()`, `locale` |
| Routes | `src/pages/[...locale]/` | Every page renders once per language |
| Head tags | `src/layouts/Base.astro` | `lang`, `dir`, canonical, `hreflang` for every language plus `x-default`, `og:locale` |
| Fonts | `src/styles/fonts-he.css`, `fonts-ja.css`, `fonts-ko.css` | Rubik and Heebo for Hebrew, Noto Sans JP and KR. Linked only on those pages. Hubot Sans and Mona Sans cover the Latin languages |
| Typography | end of `src/styles/global.css` | More leading and no negative tracking for Hebrew, Japanese and Korean; Japanese phrase breaking; Korean word breaking; code stays left to right in Hebrew |
| Diagrams | `src/components/Figure.astro` | Shows `src/assets/img/gen/<locale>/<name>.webp` when it exists, the English one otherwise |
| Checks | `npm run check:i18n` | Fails on keys English lacks, mismatched placeholders, HTML or `<code>`, and STALE translations (English changed after the translation was made) |

## Blog posts follow the reader

Every linked post exists in English (under `/en/` on akitaonrails.com) and Portuguese. `articleUrl(article, locale)` in `src/data/articles.ts` sends Portuguese readers to the Portuguese post (`ptPath`) and everyone else to the English one. `blogHome()` and `blogArchive()` do the same for the blog's home and archive. In `pt-br/articles.json` the post titles are the real Portuguese titles (listed in `docs/i18n/pt-br-post-titles.json`); in the other languages they are translations of the English titles. The Portuguese benchmark chart replaces the English one on `/pt-br/`.

Video titles on the podcasts page stay in their original Portuguese in every language; they are data, not text of this site.

## How a visitor gets their language

1. At Netlify's edge: the build writes `dist/_redirects` with one rule per page and language (`/workflow/  /pt-br/workflow/  302!  Language=pt`), matched on `Accept-Language`.
2. In the browser, as a fallback: English pages carry a few lines that do the same with `navigator.languages`.
3. The visitor's choice wins: picking a language sets an `nf_lang` cookie, which both mechanisms respect.

## Changing text

Every text change goes to all six languages in the same change.

1. Edit the English string in `src/i18n/locales/en/<namespace>.json`.
2. Update the same key in the other five folders with a real translation, following `docs/research/I18N-TRANSLATE-BRIEF.md` and `docs/i18n/glossary-<locale>.md`.
3. `npm run i18n:stamp`, then `npm run check:i18n`.

Never stamp without translating: the stamp records that the translation matches the current English.

Commands, paths, flags, product names and numbers are never translated. The `#` comments inside code blocks stay in English for now (they live in `src/data/` and the pages, not in the catalogs).

## Diagram labels

The labels inside the diagrams are listed in `src/i18n/locales/en/images.json`, with translations in each language's `images.json`. `scripts/localize-image.mjs` edits the English image with Gemini so only the words change:

```bash
node scripts/localize-image.mjs home-loop ja       # one image
node scripts/localize-image.mjs --all pt-br        # every image with labels
```

Always look at the result and compare every label with `images.json`. Hebrew, Japanese and Korean are where a model most often drops or swaps a character. If a label is wrong, run it again; if it keeps failing, delete the file and that language shows the English diagram. When an English diagram is regenerated, delete its translated copies and localize again.

## Adding a language

Add it to `languages.json`, copy `locales/en/` to the new folder and translate, add a font file and a `:lang()` rule if the script is not Latin, localize the diagrams, then `npm run i18n:stamp && npm run check:i18n && npm run build`.
